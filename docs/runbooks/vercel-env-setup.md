# Vercel env-var setup

> Required before any deploy can boot. The build fails with
> `Invalid environment variables: ...` until these are set.

## Pre-flight: rotate the three chat-pasted secrets

The following secrets were pasted in a Claude Code chat transcript and
must be considered compromised. Rotate them BEFORE setting them on
Vercel. See `handoff.md` § SECURITY for the source list.

| Secret | Where to rotate |
|---|---|
| `DATABASE_URL` password | Neon dashboard → Project → Settings → Reset Password |
| `RESEND_API_KEY` | resend.com → API Keys → revoke + issue new |
| `TURNSTILE_SECRET_KEY` | Cloudflare → Turnstile → site → Rotate Secret |

Also regenerate `BETTER_AUTH_SECRET` and `DATA_ENCRYPTION_KEY` locally
with `openssl rand -base64 32` — they were generated by Claude in chat.

Rotating `DATA_ENCRYPTION_KEY` is destructive once any ciphertext column
holds data. At Phase A.3 no PII has been encrypted yet, so this rotation
is free; it gets very expensive later.

## Required (boot blockers)

Per the failing build log:

```
Invalid environment variables: {
  BETTER_AUTH_SECRET, BETTER_AUTH_URL, DATA_ENCRYPTION_KEY
}
```

Plus database URLs from the env schema in `lib/env.ts`:

| Var | Notes |
|---|---|
| `DATABASE_URL` | Neon **pooled** URL (via pgbouncer). The app handle uses this. |
| `DATABASE_URL_UNPOOLED` | Neon **direct** URL. Migrations + crons use this. |
| `BETTER_AUTH_SECRET` | 32+ random bytes (base64). NEVER reuse local `.env.local` value — generate fresh for prod. |
| `BETTER_AUTH_URL` | Must match the deployment URL — e.g. `https://accountant.example.com` for production, `https://accountant-git-feature.example.com` for preview. Trailing slash NOT allowed. **localhost:3000 is wrong for any non-dev environment.** |
| `DATA_ENCRYPTION_KEY` | Base64 of exactly 32 raw bytes. `lib/security/kek.ts` asserts the length on boot. |

## Setting on Vercel — two paths

### Via dashboard (one-by-one)

1. Vercel project → Settings → Environment Variables.
2. For each var: key, value, scope (Production / Preview / Development).
3. `BETTER_AUTH_URL` MUST be set differently per scope:
   - Production: the production domain.
   - Preview: leave empty; Vercel injects `VERCEL_URL` automatically (the app needs a one-liner fallback — TODO).
   - Development: `http://localhost:3000`.

### Via CLI

```bash
# Install once
npm i -g vercel
vercel login
vercel link  # binds the local repo to the Vercel project

# Set each var. Vercel will prompt for the value (paste once, never logged).
vercel env add DATABASE_URL production
vercel env add DATABASE_URL_UNPOOLED production
vercel env add BETTER_AUTH_SECRET production
vercel env add BETTER_AUTH_URL production
vercel env add DATA_ENCRYPTION_KEY production
vercel env add RESEND_API_KEY production
vercel env add TURNSTILE_SITE_KEY production
vercel env add TURNSTILE_SECRET_KEY production
vercel env add NEXT_PUBLIC_TURNSTILE_SITE_KEY production

# Optional:
vercel env add AI_GATEWAY_API_KEY production
# ...

# Verify
vercel env ls production

# Trigger a fresh deploy that picks them up
vercel deploy --prod
```

## Post-deploy verification

After the first green deploy, hit these endpoints and check the
expected status:

| URL | Expect |
|---|---|
| `https://<deployment>/` | 200, landing page |
| `https://<deployment>/sign-in` | 200, sign-in panel |
| `https://<deployment>/sign-up` | 200, Turnstile widget renders |
| `https://<deployment>/api/auth/get-session` | 200 with `{user:null,session:null}` (no cookie) |

If `/api/auth/*` 500s, check the build logs for the env validator
error — the route is dynamic and runs `env()` on every request, so
missing vars surface immediately.

## Drift checks

`lib/env.ts` is the single source of truth for which vars exist.
Diff against Vercel once per quarter:

```bash
vercel env ls production --format json | jq -r '.[].key' | sort > /tmp/vercel.txt
grep -E '^\s+[A-Z_]+:' lib/env.ts | awk '{print $1}' | tr -d ':' | sort > /tmp/schema.txt
diff /tmp/schema.txt /tmp/vercel.txt
```

Empty diff = clean. Anything else = decide whether Vercel needs the
new var or the schema entry can be removed.
